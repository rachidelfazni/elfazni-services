## 0. تعليمات أساسية للمطور أو وكيل البرمجة

**نفّذ المطلوب فعليًا في المشروع، ولا تكتفِ بإنشاء واجهة وهمية (UI Mockup) أو بيانات ثابتة.** أي إضافة أو تعديل أو حذف أو نشر من لوحة الإدارة يجب أن يُحفَظ في قاعدة بيانات، وأن ينعكس على الموقع العام وفق الصلاحيات وحالة النشر. لا تُعرض أدوات الإدارة للزائر العادي.

1. افحص **المشروع الأصلي والشيفرة والملفات والأصول وطريقة النشر** قبل اختيار التقنية أو تعديل البنية.
2. اجرد جميع صفحات الموقع الحالية، وأقسام كل صفحة، وخدماتها، وصورها، وأزرارها، وروابطها، ونماذجها. أنشئ خريطة `Current Site Inventory` داخل المستودع.
3. احتفظ بنفس التصميم العام وتجربة المستخدم والألوان الأساسية والخطوط والشعار والصور والنصوص ما لم تكن هناك حاجة موثقة لتحسينها.
4. استخرج **قيم الألوان الدقيقة من CSS/Theme الحالي** واستخرج ملفات الشعار الموجودة فعلاً من المشروع؛ لا تخمّن الألوان ولا تنشئ شعارًا بديلًا.
5. اعتمد الاسم الصحيح بالعربية **«الفزني سيرفيسز»** فقط، وبالإنجليزية **ELFAZNI SERVICES**. لا تستعمل «الفظني» أو «الفاضني» أو أي تهجئة خاطئة.
6. استخدم **Bahij TheSansArabic** للعربية **إذا كان الخط متاحًا بترخيص مناسب ضمن المشروع**، مع خط بديل عربي ملائم إذا لم تتوفر ملفات مرخّصة. لا تنسخ أو تنشر ملفات خط غير مرخّصة.
7. حافظ على اتجاه **RTL** للعربية واتجاه **LTR** للتركية والإنجليزية والفرنسية، مع ضبط المحاذاة والحقول والقوائم بشكل صحيح.
8. نفّذ البنية على مراحل، مع اختبارات وتشغيل فعلي. لا تترك بيانات تجريبية أو أسرارًا أو حسابات افتراضية مكشوفة في الإنتاج.
9. **قيود المعاينة:** تم التحقق من رابط الموقع وعنوانه العام، لكن لا توجد في هذا المستند معاينة موثوقة لشيفرته أو جميع صفحاته الداخلية. لذلك فإن أي صفحة أو خدمة غير مؤكدة هنا هي **ميزة مطلوب دعمها عند الحاجة** وليست ادعاءً بأنها موجودة حاليًا.

## 1. الرؤية والنتيجة النهائية

إنشاء **CMS مخصّص** (Content Management System) مع **Admin Dashboard** متكامل ضمن نفس المنظومة، بحيث يمكن للمسؤول من المتصفح، دون تعديل الكود:

- إدارة كل النصوص والعناوين والفقرات والصور ومقاطع الفيديو في الصفحات.
- إضافة صفحات أو أقسام وحذفها وإخفاؤها وتغيير ترتيبها وتحرير خصائصها.
- إضافة الخدمات وتعديل العنوان والوصف والصور والأيقونات والروابط وترتيب العرض وحالة الظهور.
- إنشاء مقالات ومدونة احترافية وتصنيفات ووسوم وصور مميزة ومسودات وجدولة نشر.
- إدارة ملفات الوسائط: رفع، استبدال، قص، ضغط، حذف آمن، معلومات بديلة `alt`.
- إدارة بيانات العلامة التجارية، الشعار، أيقونة الموقع، بيانات التواصل، روابط الشبكات الاجتماعية، معلومات المسؤول وصورته الشخصية.
- التحكم بالقوائم العلوية والسفلية وأزرار الدعوة إلى الإجراء وبيانات SEO.
- الاطلاع على الرسائل الواردة من نماذج التواصل وإدارتها، إن كانت النماذج موجودة أو أُضيفت.
- إدارة المستخدمين الإداريين والصلاحيات وسجل التعديلات والنسخ الاحتياطية.
- دعم تعدد اللغات إن كان الموقع متعدد اللغات أو عند تفعيله.

**معيار الإنجاز الرئيسي:** يستطيع مالك الموقع تحديث محتوى صفحة رئيسية وخدمة ومقال وصورة عبر `/admin`، وتظهر النسخة المنشورة في الموقع العام بعد الحفظ/النشر دون فتح محرّر الأكواد أو إعادة بناء يدوية.

## 2. المعمارية المقترحة مع احترام المشروع الحالي

### 2.1 قاعدة القرار التقني

**لا تُعد بناء الموقع من الصفر بشكل تلقائي.** أولًا افحص `package.json`، إطار الواجهة، نظام التوجيه، الاستضافة، المكونات، الاتصال الخلفي، ومتغيرات البيئة. اختر أقل تغيير يحقق إدارة مستمرة وآمنة للمحتوى.

- إن كان الموقع React/Vite أو تطبيق SPA ثابتًا: احتفظ بمكونات التصميم، وأضف Backend حقيقيًا وقاعدة بيانات وتخزين ملفات ونظام مصادقة؛ حل قابل للتطبيق هو **Supabase (PostgreSQL + Auth + Storage)** مع طبقة خادم آمنة أو Edge Functions للعمليات الحساسة.
- إن كان المشروع Next.js أو إطار SSR: استعمل مسارات خادم محمية وPostgreSQL، مع دعم الخادم/المحتوى المنشور من أجل SEO.
- إن كان المشروع قائمًا على Backend أو CMS: مدّده بدل تكرار قواعد بيانات أو إنشاء نظام دخول ثانٍ غير ضروري.
- إن كان تشغيل الموقع في منصة AI Studio الحالية لا يدعم البيانات الدائمة أو مسارات الخادم المطلوبة: **انقل النشر إلى بيئة مناسبة بعد حفظ المصدر والتصميم والنطاق**، ثم اربط الدومين الحالي إن كان ممكنًا. لا تفترض أن البيئة الحالية تدعم Backend دائمًا.

### 2.2 مكوّنات النظام

```text
الزائر
  └── الموقع العام (Public Website)
        ├── صفحات + أقسام ديناميكية
        ├── خدمات + تفاصيل الخدمة
        ├── مدونة + تفاصيل المقال
        ├── وسائط + SEO
        └── نماذج تواصل عامة محمية

المسؤول / المحرر
  └── /admin/login -> /admin
        ├── المحتوى والصفحات والأقسام
        ├── الخدمات والتصنيفات
        ├── المدونة والمقالات
        ├── الوسائط والملفات
        ├── الإعدادات والهوية والملف الشخصي
        ├── الرسائل والمستخدمون
        └── سجل الأنشطة والصلاحيات

خادم آمن + Auth + DB + Object Storage + Backups
```

### 2.3 قواعد غير قابلة للتفاوض

- لا تحفظ المحتوى الرئيسي في `localStorage` أو JSON محلي على أنه نظام إدارة إنتاجي.
- لا تضع كلمات مرور أو `service_role` أو مفاتيح قاعدة البيانات الخاصة ضمن كود المتصفح.
- كل عملية كتابة يجب التحقق من صلاحيتها **على الخادم** أو عبر قواعد RLS محكمة، وليس بمجرد إخفاء زر في الواجهة.
- تعتمد صفحات الموقع العامة على **المحتوى المنشور فقط**، ولا تعرض المسودات أو البيانات السرية.
- لا تحذف المحتوى أو الصور المستخدمة في صفحات أخرى بصورة صامتة؛ أظهر أثر الحذف قبل تنفيذه.
- وثّق أي ترحيل أو تحويل تقني وكيفية العودة للإصدار السابق.

## 3. لوحة الإدارة — الشكل وتجربة الاستخدام

**مسار الإدارة:** `/admin` — **تسجيل الدخول:** `/admin/login`  
مسارات بديلة لمنظومة اللغات إن اقتضى المشروع، مع إبقاء مسارات الإدارة ثابتة وواضحة.

### 3.1 التصميم

- لوحة تحكم متجاوبة مع الكمبيوتر والتابلت والهاتف، والعربية هي اللغة الافتراضية للوحة.
- شريط جانبي قابل للطي، وشريط علوي للبحث والإشعارات واسم المستخدم وصورته.
- ألوان الخلفيات والأزرار والحالات مستمدة من **Design Tokens الحقيقية** للموقع العام.
- واجهة هادئة، مساحات مناسبة، بطاقات إحصائية قليلة، لا ازدحام أو تكرار.
- دعم الوضع الفاتح، وإضافة الوضع الداكن فقط إذا أمكن دون الإخلال بالهوية.
- مؤشرات لحالة المحتوى: **مسودة، مجدول، منشور، مؤرشف**، مع رسائل تحقق وتأكيد الأخطاء.
- دعم الجداول: بحث، تصفية، فرز، تحديد متعدد، ترقيم صفحات، إجراءات جماعية محدودة بحسب الصلاحية.
- إمكانية معاينة التعديل قبل النشر والعودة لإصدار محفوظ.

### 3.2 الصفحة الرئيسية للإدارة

اعرض بطاقات للبيانات الحقيقية فقط: عدد الصفحات والخدمات المنشورة، المقالات المنشورة/المسودة، الوسائط، الرسائل الجديدة. اعرض قائمة **آخر التعديلات** و**مسودات تحتاج مراجعة** و**آخر الرسائل** إن كان النظام يدعمها. لا تعرض أرقام زيارات وهمية؛ لا تظهر التحليلات إلا بعد ربط مصدر قياس حقيقي مناسب للخصوصية.

### 3.3 أقسام القائمة الرئيسية

1. **نظرة عامة** — `/admin`
2. **الصفحات والأقسام** — `/admin/pages`
3. **الخدمات** — `/admin/services`
4. **المدونة والمقالات** — `/admin/blog/posts`
5. **التصنيفات والوسوم** — `/admin/blog/categories` و`/admin/blog/tags`
6. **مكتبة الوسائط** — `/admin/media`
7. **القوائم والتنقل** — `/admin/navigation`
8. **الرسائل والطلبات** — `/admin/inbox` (إذا طُبّقت نماذج)
9. **الهوية ومعلومات الموقع** — `/admin/settings/branding`
10. **التواصل والروابط** — `/admin/settings/contact`
11. **SEO وإعدادات النشر** — `/admin/settings/seo`
12. **المستخدمون والصلاحيات** — `/admin/users`
13. **الملف الشخصي** — `/admin/profile`
14. **سجل النشاطات والنسخ الاحتياطية** — `/admin/audit` و`/admin/backups`

عناصر القائمة تُعرض حسب دور المستخدم؛ المسارات نفسها محمية مهما كان شكل الواجهة.

## 4. تسجيل الدخول والمستخدمون والصلاحيات

### 4.1 المصادقة

- دخول بالبريد الإلكتروني وكلمة مرور قوية، مع التحقق من البريد واستعادة كلمة المرور.
- تفعيل **MFA/2FA** لحساب المالك، ويفضّل لجميع المدراء.
- عدم إتاحة التسجيل الإداري العام. إضافة المديرين تكون **بدعوة من مسؤول مخوّل**.
- تقييد محاولات الدخول، وإدارة الجلسات، وإنهاء الجلسات، و`logout` حقيقي.
- إذا كانت الجلسات عبر Cookies: استخدم `HttpOnly`, `Secure`, و`SameSite` وحماية CSRF المناسبة. لا تضع أسرارًا في `localStorage`.
- لا تكتب أي بريد أو كلمة مرور ثابتين في المستودع. إنشاء أول مدير عبر إجراء إعداد محمي، لا عبر مستخدم افتراضي معروف.
- حماية `/admin/**` على مستوى الخادم/الخلفية، وإعادة الزائر غير المخوّل إلى صفحة الدخول.

### 4.2 الأدوار والصلاحيات

| الدور | الصفحات | الخدمات | المقالات | الوسائط | المستخدمون | الإعدادات |
|---|---|---|---|---|---|---|
| Owner / Super Admin | كامل | كامل | كامل | كامل | كامل | كامل |
| Admin | كامل* | كامل | كامل | كامل | حسب التفويض | حسب التفويض |
| Editor | تحرير/نشر | تحرير/نشر | تحرير/نشر | إدارة | لا | لا |
| Author | لا | لا | مقالاته كمسودات | رفع محدود | لا | لا |
| Viewer / Support | قراءة ما صُرح به | قراءة | قراءة | قراءة | لا | لا |

\* يمكن تخصيص صلاحيات `Admin` منعًا لتغيير ملكية الموقع أو أسرار الخدمات. استخدم RBAC بصلاحيات أدق مثل `posts.create`, `posts.publish`, `services.delete`, `settings.edit`, `users.invite`، وفرضها في جميع نقاط API وقواعد البيانات.

### 4.3 حسابي

الاسم، صورة المستخدم، البريد، لغة لوحة التحكم، تغيير كلمة المرور، MFA، الجلسات النشطة، وسجل نشاط الحساب. **فرّق بين الملف الشخصي للمدير (خاص) وبين نبذة المالك وصورته العامة التي تظهر على الموقع**.

## 5. إدارة الصفحات والأقسام — Page Builder آمن

### 5.1 إدارة الصفحات

- إضافة صفحة جديدة (العنوان، مسار URL/slug، اللغة، حالة النشر، قالب الصفحة، بيانات SEO).
- تعديل النصوص والوسائط والمكونات دون تعديل الكود.
- نسخ صفحة، معاينتها، حفظ مسودة، نشرها، إخفاؤها أو أرشفتها، واسترجاعها من سلة المحذوفات.
- اختيار ظهور الصفحة ضمن القائمة، ومنع التضارب في المسارات.
- دعم ترتيب الصفحات، توجيه مسار قديم إلى جديد `301` عند تغيير `slug`.

### 5.2 إدارة الأقسام داخل الصفحة

يُنفَّذ محرر أقسام مبني على **قوالب جاهزة وآمنة**، لا يُسمح فيه بحقن HTML/JavaScript حر. الأنواع المقترحة:

| نوع القسم | الحقول القابلة للتحرير |
|---|---|
| Hero | عنوان، وصف، صورة/فيديو، زر/زرين، محاذاة وخلفية |
| Text / Rich Text | عنوان، نص منسّق آمن، صورة اختيارية |
| Services Grid | عنوان، خدمات مختارة، عدد الأعمدة والترتيب |
| Image Gallery | صور، نص بديل، شرح، ترتيب |
| CTA | عنوان، وصف، زر، رابط، صورة خلفية |
| FAQ | أسئلة وأجوبة مع ترتيب |
| Testimonials | شهادات معتمدة إن وجدت، وأسماء مع موافقة |
| Stats | أرقام حقيقية قابلة للتحرير، بدون ادعاءات غير موثقة |
| Contact | معلومات التواصل، أزرار أو نموذج تواصل |
| Blog Highlights | مقالات مختارة أو أحدث المقالات المنشورة |
| Feature Cards | قائمة بطاقات مع عنوان ووصف وأيقونة/صورة |

**الوظائف:** إضافة قسم، تعديل، نسخ، سحب للإعادة والترتيب، إخفاء مؤقت، حذف إلى السلة، معاينة سطح المكتب والهاتف، ترجمة محتواه، ومراجعة الإصدار قبل النشر. يجب أن تبقى جميع الأقسام ضمن نظام تصميم الموقع نفسه، مع حدود لضبط الصور وطول النصوص والمسافات.

**مهم:** اربط **كل أقسام الموقع الحالية** بأنواع قابلة للإدارة، حتى إن كانت بعض الأقسام مخصّصة وغير مذكورة في الجدول. لا تختفِ أقسام من الموقع بسبب نقص أنواع المحرّر؛ أنشئ لها `block type` خاصًا.

## 6. إدارة الخدمات

كل خدمة عنصر مستقل قابل للنشر وله صفحة تفاصيل اختيارية، ويمكن إظهارها على الصفحة الرئيسية أو في صفحات أخرى.

### 6.1 حقول الخدمة

- معرّف ثابت (`id`)، العنوان عربيًا وترجماته، `slug` فريد لكل لغة.
- وصف مختصر، وصف مفصّل منسّق، نقاط توضيحية، صورة رئيسية، معرض صور اختياري.
- أيقونة من مكتبة أيقونات موحّدة، وتصنيف الخدمة وترتيبها.
- زر الدعوة إلى الإجراء: النص، نوعه (رابط داخلي/خارجي/واتساب/طلب استفسار)، الوجهة.
- حالة الخدمة: مسودة، منشورة، مخفية، مؤرشفة.
- تحسينات SEO: عنوان ووصف ومحرك بحث وصورة مشاركة ورابط canonical.
- بيانات اختيارية منظَّمة مثل المتطلبات وخطوات الخدمة والأسئلة الشائعة، دون فرض معلومات سعرية إذا لم تكن موجودة.
- صاحب التعديل، تواريخ الإنشاء والتحديث والنشر، رقم الإصدار.

### 6.2 عمليات الإدارة

**إنشاء، تعديل، نشر، سحب من النشر، ترتيب بالسحب، نسخ، حذف مع إمكانية استعادة، معاينة، ترجمة.** إذا حُذفت خدمة تشير إليها أقسام/قوائم، أظهر تحذيرًا مع الروابط المتأثرة قبل الحذف.

### 6.3 أصناف الخدمات

أضف تصنيفات يمكن إدارتها (الاسم، الوصف، الأيقونة، الترتيب، حالة النشر). لا تفترض مسبقًا أن جميع هذه الخدمات ظاهرة على الموقع؛ يمكن دعم الأنواع التي يختارها المالك مثل **خدمات القنصلية المغربية، حجوزات الطيران والفنادق، الإقامات والتأشيرات** بناءً على المحتوى الموجود فعليًا. لا تستخدم نصوصًا تَعِد بنتيجة قانونية أو قنصلية مضمونة.

## 7. المدونة المتكاملة — Blog CMS

### 7.1 الواجهة العامة

- فهرس مدونة على `/blog` (أو مسارات مترجمة إن كان معتمدًا) مع تصميم مطابق للموقع.
- بطاقات مقالات: الصورة المميزة، العنوان، ملخص، الفئة، تاريخ النشر، الرابط.
- صفحة مقال `/blog/{slug}` مع عنوان واضح، صورة، نص منسق، عناوين فرعية، روابط، صور داخلية، تاريخ، واسم الكاتب إذا كان معدًّا للنشر.
- صفحات تصنيفات، بحث بالمقالات، روابط مقالات ذات صلة، وترقيم صفحات أو تحميل لاحق آمن.
- قراءة مريحة للعربية RTL على الهاتف، مع تباعد جيد وتنسيق صور ومحتوى طويل.
- لا تظهر المقالات غير المنشورة ولا صفحاتها في الفهرسة العامة.

### 7.2 محرّر المقالات

أنشئ محرّرًا غنيًا موثوقًا (Rich Text / Block Editor) يدعم:

- العناوين `H2/H3`، الفقرات، الخط العريض، القوائم، الاقتباسات، الروابط، الجداول الأساسية، الصور والتعليقات.
- إدراج الصور من المكتبة أو رفع صورة مباشرة، مع إضافة `alt` وشرح الصورة والاعتماد.
- صورة مميزة للمقال، الملخص، الكاتب، التصنيف الأساسي، عدة وسوم.
- `slug` قابل للتحرير، عنوان SEO ووصف Meta وصورة Open Graph.
- حفظ تلقائي مع إشعار بالحفظ، مسودة، معاينة، مراجعات، نشر فوري أو جدولة.
- تحذير قبل مغادرة الصفحة عند وجود تعديلات غير محفوظة.
- عند لصق HTML أو نص من مصدر خارجي يتم تنقيته؛ **لا تسمح بتشغيل scripts أو handlers أو iframes غير موثوقة**.
- مراعاة الروابط الخارجية (`rel` المناسب) وسهولة الوصول عبر العناوين البديلة وتدرّج العناوين.

### 7.3 سير النشر

`Draft → In Review (اختياري) → Scheduled / Published → Archived`

- يمكن للكاتب إنشاء مسودة دون نشرها إذا لم يكن لديه تصريح.
- يُسجل وقت النشر الفعلي والمنطقة الزمنية، ووقت آخر تحديث.
- يجب وجود Job/Cron أو آلية موثوقة لتفعيل النشر المجدول، وليس الاعتماد على متصفح المدير المفتوح.
- عند سحب مقال من النشر، يختفي من نتائج البحث العامة و`/sitemap.xml`.
- احتفظ بتاريخ المراجعات مع إمكان المقارنة والاستعادة.

### 7.4 إدارة التصنيفات والوسوم

إنشاء/تعديل/حذف/دمج فئات ووسوم، اختيار الفئة الافتراضية، عرض عدد المقالات لكل فئة، ومنع حذف فئة مستخدمة دون معالجة ارتباطاتها. مسارات الفئات والوسوم قابلة للترجمة عند دعم اللغات.

### 7.5 التعليقات والنشرة البريدية

لا تفعّل التعليقات العامة أو الاشتراكات البريدية تلقائيًا. إن طلب المالك تفعيلها لاحقًا، أضف إشرافًا ومكافحة رسائل غير مرغوبة وموافقة واضحة وسياسة خصوصية؛ وإن لم يطلبها، **اتركها معطّلة** للحفاظ على بساطة النظام.

## 8. مكتبة الصور والفيديو والملفات

### 8.1 الرفع والإدارة

- رفع بالضغط أو السحب والإفلات، ورفع متعدد مع شريط تقدم.
- صور: `JPEG/PNG/WebP/AVIF` وفق توافق البنية. ملفات أخرى مثل PDF بحسب سياسة الموقع. لا تسمح بامتدادات تنفيذية أو SVG غير منقح.
- تحقق من الحجم والنوع الحقيقي `MIME` والحدود على الخادم، مع أسماء ومسارات آمنة غير قابلة للتخمين.
- إنشاء أحجام مناسبة للعرض والصور المصغرة، وضغط دون فقد مفرط للجودة، واستخدام Lazy Loading.
- تنظيم مكتبة قابلة للبحث بالاسم والنوع والتاريخ، ومجلدات/مجموعات افتراضية عند الحاجة.
- حقول: `title`, `alt_text` حسب اللغة، `caption`, `credit`, `file_size`, `width`, `height`, `uploaded_by`, `created_at`.
- قص/تحديد نقطة التركيز `focal point` ومعاينة مكان عرض الصورة.
- إظهار مكان استعمال كل صورة قبل الحذف؛ إمكان **استبدال الأصل** مع تحديث استعمالاته أو رفع نسخة منفصلة.
- الاحتفاظ بنسخ احتياطية أو نسخة أصلية إذا كان القص/التحسين سيؤثر عليها.
- تقييد أنواع الملفات القابلة للتقديم علنًا؛ الملفات الخاصة لا تحصل على روابط عامة ثابتة.

### 8.2 الهوية البصرية

خصص داخل المكتبة تبويب **Brand Assets** للشعار الرئيسي، شعار الوضع الداكن/الفاتح إن وجد، `favicon`, وصور المشاركة الاجتماعية. **استعمل الأصول الفعلية للموقع** ولا تنشئ شعارات بديلة تلقائيًا. تأكد من أن استبدال الصورة في لوحة الإدارة يغيّر الموقع فعليًا عبر روابط الوسائط المخزّنة.

### 9.3 شريط التنقل والتذييل

إنشاء القوائم والعناصر وترتيبها، روابط داخلية أو خارجية، إظهار/إخفاء، عناصر متداخلة عند الحاجة، قوائم مختلفة للهاتف والتذييل إن كان التصميم يستعمل ذلك، والتحقق من سلامة الروابط.

### 9.4 نماذج التواصل

عند وجود نموذج تواصل أو إضافته: اجعل العنوان والوصف والحقول الاختيارية ورسالة النجاح قابلة للتحرير؛ واحفظ الرسائل في قاعدة البيانات بأقل بيانات لازمة. ادعم حالة `new/read/replied/archived` دون ادعاء إرسال بريد إذا لم يوجد موفر بريد مُهيأ بالفعل.

## 10. تعدد اللغات

- دعم العربية أساسًا، والتركية والإنجليزية/الفرنسية **بحسب اللغات الموجودة أو التي تُفعَّل إداريًا**.
- يجب أن تكون الصفحات والخدمات والمقالات وعناوين SEO قابلة للترجمة بشكل مستقل.
- يُفضَّل تخزين النصوص المترجمة في جداول Translation أو بيانات منظَّمة، وليس نسخ موقع كامل منفصل لكل لغة.
- `slug` فريد ضمن نوع المحتوى واللغة؛ احفظ رابط اللغة المقابلة لنفس المحتوى.
- لا تعرض ترجمة غير مكتملة على أنها ترجمة رسمية؛ ضع حالة `translation_status`، وحدد سلوك fallback بوضوح.
- تعامل مع اتجاه العربية واللغات الأخرى في المحرر والواجهة ومحتوى البحث.
- إذا أُنشئت روابط خاصة بكل لغة، طبّق `hreflang` و`canonical` بشكل صحيح.

### 11.1 قواعد البيانات

- مفاتيح أساسية `UUID`، ومفاتيح خارجية مع تصرف حذف محدد، و`created_at/updated_at`.
- قيود تمنع تكرار `slug` ضمن المسار واللغة وحالة التداخل ذات الصلة.
- فهارس لحالات النشر وتاريخ النشر والتصنيف، وفهارس بحث مناسبة للمقالات.
- استعمل `soft delete`/`deleted_at` للمحتوى المهم؛ الإزالة النهائية مسار منفصل ومحمي.
- لا تضع معلومات دخول أو رسائل خاصة ضمن `site_settings` العامة أو استعلامات الموقع العام.
- راعِ قيود العلاقة عند حذف صورة أو تصنيف أو صفحة، حتى لا تنشأ روابط معطلة.
- خزن وقت الأحداث بصيغة UTC واعرضه بتوقيت الإدارة وفق `Europe/Istanbul`.
- استعمل معاملات `transactions` للتعديلات المركّبة والترجمات وحفظ ترتيب الأقسام.

### 11.2 قواعد الوصول RLS / Backend Authorization

- القراءة العامة محصورة بالمحتوى `published` وغير المحذوف، مع مراعاة `published_at`.
- جميع عمليات الإنشاء والتحديث والحذف تتطلب مصادقة وصلاحية خاصة بالنوع والفعل.
- حساب الكاتب لا يستطيع تعديل/نشر مقالات الآخرين إلا إذا مُنح تصريحًا صريحًا.
- `contact_submissions`, `audit_logs`, `users`, `revisions` ليست جداول عامة.
- استخدم روابط موقّعة قصيرة العمر للملفات الخاصة، وملفات عامة فقط للأصول المنشورة.
- اختبر أن المتصفح المجهول لا يمكنه تنفيذ `INSERT/UPDATE/DELETE` مباشر عبر SDK.

## 12. واجهات API والعمليات

نفّذ وفق إطار العمل (Server Routes/Actions أو REST). الأسماء أدناه **مرجعية للعقود** وليست فرضًا على جميع الأطر.

| المجال | عمليات مطلوبة |
|---|---|
| Auth | login, logout, session, password-reset, MFA, invite |
| Pages | list, get, create, update, preview, publish, unpublish, trash, restore, reorder |
| Blocks | create, edit, duplicate, move, enable/disable, delete |
| Services | CRUD, categories, reorder, translation, publish/unpublish |
| Posts | CRUD, rich content save, revisions, schedule, publish/unpublish |
| Blog taxonomy | categories, tags, assignment, translation |
| Media | signed upload, validate, process, list, update metadata, replace, safe delete |
| Navigation | list, edit, reorder, validate links |
| Settings | scoped get/update, branding, contact, SEO, public profile |
| Inbox | submit public form (with validation/anti-spam), admin list/status/delete |
| Admin | role assignment, audit logs, health check, backup status |

**API Quality:** تحقق إدخال server-side (مثل Zod/JSON Schema)، أخطاء موحّدة، pagination/filter/sort، حماية rate limit، منع Mass Assignment، و`idempotency` حيث يلزم. لا تسمح بتمرير حقول `role`, `is_admin`, `published_at` أو `owner_id` من المستخدم العام دون تفويض واضح.

**النشر/التخزين المؤقت:** عند نشر/تعديل محتوى، يجب إبطال Cache أو إعادة التحقق (`revalidate`) على المسارات المتأثرة، وتحديث `sitemap` وبيانات البحث المرتبطة. يُمنع ظهور بيانات قديمة لساعات دون آلية واضحة للتحديث.

## 13. SEO والمشاركة والأداء

### SEO

- عنوان فريد، Meta Description، `canonical` وصورة Open Graph لكل صفحة/خدمة/مقال منشور.
- `sitemap.xml` ديناميكي يتضمن المنشور فقط، و`robots.txt` صحيح يستبعد صفحات الإدارة ومسارات المعاينات.
- بنية عناوين صحيحة: `H1` واحد مناسب، ثم `H2/H3`، مع `alt` للصور.
- Structured Data مناسب حيث ينطبق (Organization، BreadcrumbList، Article، Service)، **من دون اختلاق تقييمات أو مزايا أو أسعار**.
- روابط 301 عند تغيير `slug`، وصفحة 404 مناسبة، وتفادي المحتوى المكرر بين اللغات.
- حتى تكون المدونة قابلة للفهرسة بشكل جيد، تأكد أن نص المقال وMeta يظهران لمحركات البحث عبر SSR أو SSG أو prerender مكافئ؛ SPA لا تُعتمد وحدها دون فحص فعلي للفهرسة.

### الأداء وتجربة المستخدم

- صور متجاوبة `srcset`, ضغط مناسب، Lazy Loading للصور غير الأساسية.
- تقليل JavaScript العامة؛ لا تُحمّل حزم محرر الإدارة في صفحات الزوار.
- ثبات التخطيط `CLS`، واستجابة جيدة للتفاعل، واختبارات Lighthouse على الهاتف.
- واجهة قابلة للاستخدام عبر لوحة المفاتيح، تباين مناسب، تسميات للحقول، حالات تحميل وأخطاء واضحة.
- تخطيط متجاوب للشاشات المختلفة، خاصة صفحات الخدمات والمقالات والإدارة.

## 14. الخصوصية والأمن والنسخ الاحتياطية

### الأمن

- فرض HTTPS، إدارة أسرار البيئة، قفل CORS للنطاقات المصرح بها.
- التحقق من الصلاحيات في الخادم وفي قواعد البيانات، لا في الواجهة وحدها.
- الحماية من XSS وSQL Injection وCSRF ورفع ملفات خبيثة وBrute Force.
- `Content Security Policy` وقيود تضمين الموارد عند الإمكان.
- ضبط محاولات إرسال النماذج، وحماية spam لا تعتمد فقط على CAPTCHA.
- تسجيل تغييرات الإعدادات والصلاحيات والبيانات المنشورة في Audit Log (المستخدم، الفعل، الوقت، الهدف).
- تجنّب تخزين محتوى حساس داخل سجلات الأخطاء، وامنع عرض stack traces للزوار.

### الخصوصية

- إذا جُمعت طلبات تواصل، اقتصر على أقل قدر من المعلومات الضرورية، ووفّر سياسة خصوصية وفترات احتفاظ وحذف مناسبة.
- افصل رسائل العملاء ومعلوماتهم عن المحتوى العام. لا تضع بيانات قنصلية/هويات/إقامات حساسة في المدونة أو الوسائط العامة.
- راجع التزامات **KVKK التركية** وأي قواعد حماية بيانات أخرى تنطبق حسب مكان العملاء والاستضافة والخدمة؛ يلزم اعتماد الصياغات القانونية من مختص عند الحاجة.
- لا تُرسل إشعارات بريدية تسويقية دون موافقة مناسبة، ولا تنشر صورة أو شهادة عميل بلا موافقة.

### النسخ الاحتياطية والاستعادة

- نسخ احتياطي دوري لقاعدة البيانات ووسائط التخزين وملفات الإعدادات اللازمة لإعادة النشر، مع تشفير وضبط وصول.
- تحديد سياسة حفظ مناسبة حسب حجم العمل والاستضافة، مع نسخة مستقلة عن خدمة الإنتاج إن أمكن.
- توثيق **خطوات الاستعادة** واختبارها على بيئة غير إنتاجية دوريًا.
- عند حذف مقال/قسم، أمّن إمكانية استعادة سهلة قبل الحذف النهائي.

| `/services/{slug}` | صفحة تفاصيل خدمة |
| `/blog` | المقالات المنشورة |
| `/blog/{slug}` | صفحة المقال |
| `/blog/category/{slug}` | مقالات حسب التصنيف |
| `/contact` | تواصل إن وجد أو عند إضافته |
| `/admin/login` | تسجيل الدخول |
| `/admin` | النظرة العامة |
| `/admin/pages` | الصفحات والأقسام |
| `/admin/services` | الخدمات |
| `/admin/blog/posts` | المقالات |
| `/admin/media` | مكتبة الوسائط |
| `/admin/settings` | إعدادات عامة |
| `/admin/profile` | الملف الشخصي الإداري |

للنسخ متعددة اللغات: اعتمد سياسة routing واحدة متماسكة مثل `/ar/blog/...` و`/tr/blog/...` **فقط إذا كانت مناسبة للروابط الحالية**.

## 16. ترحيل الموقع الحالي دون فقد المحتوى

**هذه المرحلة إلزامية قبل تفعيل إدارة المحتوى في الإنتاج.**

1. أنشئ نسخة احتياطية من الكود/الأصول/بيانات البيئة ووثّق طريقة النشر الحالية.
2. استخرج **قائمة دقيقة** لكل صفحة موجودة، أسماء أقسامها، ترتيبها، محتواها، روابطها، صورها وأيقوناتها.
3. حدد مصادر البيانات الثابتة الحالية (مصفوفات، JSX، JSON، HTML، ملفات ترجمة).
4. أنشئ الجداول والمهاجرات `migrations` أولًا ثم اكتب عملية `seed/import` قابلة للتكرار بأمان دون ازدواجية.
5. انقل المحتوى الحقيقي الحالي إلى قاعدة البيانات مع الإبقاء على نفس النصوص والصور والروابط والظهور والترتيب.
6. حوّل المكونات العامة للقراءة من CMS؛ لا تنشئ نسخة تصميم ثانية غير متناسقة.
7. تأكد من صلاحية الصور/الخطوط والشعار بعد النشر وتوافق الروابط القديمة.
8. قارن Screenshot قبل وبعد على Desktop وMobile للصفحات الرئيسية والمهمة، وأصلح الفروقات غير المقصودة.
9. اختبر التحرير والنشر والحذف والاستعادة وإبطال التخزين المؤقت على بيئة Staging.
10. انشر تدريجيًا مع خطة Rollback؛ لا تحذف المصدر القديم أو تغيّر DNS قبل التأكد من سلامة النسخة الجديدة.

**المطلوب تسليمه:** ملف inventory، خريطة مكوّنات-to-CMS، أوامر migration/seed، سجل التغييرات، نسخة تجريبية، وخطة العودة.

## 17. مراحل التنفيذ المقترحة والأولويات

### المرحلة A — تدقيق الأساس والتجهيز (إلزامية)

- فحص المستودع والتقنيات والمكونات والألوان والخط والشعار والمسارات والمحتوى الحالي.
- القرار المعماري النهائي، التوافق مع النشر، إعداد البيئات: development/staging/production.
- إنشاء قاعدة بيانات، Auth، Storage، ومهاجرات أساسية.

### المرحلة B — الإدارة الأساسية (MVP إلزامية)

- تسجيل دخول آمن، Owner، أدوار وصلاحيات.
- لوحة تحكم وتخطيط RTL متوافق مع الهوية.
- مكتبة الوسائط، إعدادات الموقع العامة، إدارة الملف والصورة العامة.
- إدارة الخدمات، تعديل صور ونصوص الصفحة الرئيسية، نشر التغييرات.

### المرحلة C — الصفحات والمدونة (إلزامية)

- إدارة الصفحات والأقسام مع السحب والترتيب والمعاينة.
- إدارة المقالات بتنسيق غني وصور مميزة وتصنيفات ووسوم.
- فهرس مدونة عام وصفحات مقالات مع SEO و`published` filtering.

### المرحلة D — التوسع والحماية (إلزامية للإطلاق)

- كامل جرد وترحيل المحتوى الحالي، اختبارات أمن وصلاحيات، سجل الأنشطة.
- وظائف النسخ الاحتياطي/استعادة، مراجعات المحتوى، رسائل التواصل عند وجودها.
- تحسين الأداء، الموبايل، الوصول، الروابط، sitemaps، التحقق من النشر.

### المرحلة E — ميزات متقدمة (بعد اكتمال الأساس)

- نشر مجدول، إشعارات داخلية، تحليلات حقيقية، ترجمة متقدمة، Workflow مراجعة، بحث متقدم، استيراد/تصدير محتوى.
- خدمات CRM أو حجوزات أو دفع **لا تُضاف تلقائيًا**؛ تُنفّذ لاحقًا فقط إذا تم تحديد متطلبات وحقوق وصول وحماية بيانات منفصلة.

## 18. اختبارات القبول النهائية (Definition of Done)

لا تعتبر المهمة مكتملة حتى تنجح الاختبارات التالية على بيئة منشورة ومربوطة بقاعدة بيانات فعلية:

### المحتوى

- [ ] عند إضافة خدمة جديدة ونشرها، تظهر بالمكان الصحيح ولها رابط يعمل.
- [ ] عند تعديل وصف الخدمة وصورتها من `/admin`، يتغير الموقع العام بعد النشر.
- [ ] عند حذف خدمة إلى السلة، تختفي من الموقع ويمكن استعادتها.
- [ ] عند تعديل عنوان Hero أو إضافة قسم على الصفحة الرئيسية، تظهر النتيجة الفعلية دون تعديل الكود.
- [ ] يمكن تغيير ترتيب الأقسام وحفظه؛ يبقى بعد إعادة تحميل المتصفح.
- [ ] يمكن إخفاء قسم دون حذفه وإعادته لاحقًا.
- [ ] يمكن تعديل رقم واتساب والبريد والشعار والصورة العامة للمسؤول من الإعدادات وينعكس ذلك في الواجهة المعنية.

### المدونة

- [ ] يمكن إنشاء مقال بالعربية مع صورة مميزة وصور داخلية وعناوين وروابط.
- [ ] يمكن وضع المقال في مسودة، ولا يظهر علنًا أو في Sitemap.
- [ ] يمكن معاينته بصلاحية مناسبة ثم نشره ليظهر في `/blog` وصفحته.
- [ ] تعمل التصنيفات والوسوم والبحث والترقيم دون عرض مسودات.
- [ ] تعمل تعديلات عنوان SEO والوصف والصورة الاجتماعية ومعلومات Article.
- [ ] يمكن تحديث المقال واسترجاع نسخة محفوظة سابقة.

### الوسائط والإدارة

- [ ] رفع صورة وتعيين النص البديل، ثم اختيارها في خدمة أو مقال أو قسم.
- [ ] لا تقبل الملفات التنفيذية أو الملفات التي تتجاوز الحدود المحددة.
- [ ] حذف صورة مستخدمة يسبقُه تحذير واضح ويمنع كسر الصفحات.
- [ ] المستخدم غير المسجل لا يدخل `/admin` ولا يقرأ endpoints خاصة.
- [ ] الكاتب لا يمكنه تعديل دور حسابه أو نشر مقال بلا صلاحية.
- [ ] لا يمكن تجاوز قيود الصلاحيات بإرسال API مباشر.
- [ ] لا تحتوي ملفات الإنتاج على كلمة مرور أو مفتاح خدمة سري في حزمة المتصفح.
- [ ] تظهر العمليات الحساسة في Audit Log.

### التصميم والنشر

- [ ] يشبه الموقع بعد الترحيل التصميم الأصلي في الألوان والخطوط والشعار والأقسام ومقاسات الصور.
- [ ] تعمل العربية RTL واللغات المتاحة LTR بشكل صحيح على الموبايل والكمبيوتر.
- [ ] لا تنكسر أي روابط أساسية؛ تعمل 301 للروابط التي تغيرت.
- [ ] الصفحات المنشورة والمقالات قابلة للفهرسة، وصفحات الإدارة محجوبة.
- [ ] يوجد backup قابل للاستعادة ومجرَّب، ولا تُفقد البيانات عند تحديث التطبيق.
- [ ] نجاح Build وLint وTypecheck واختبارات صلاحيات وحالات النشر الأساسية.
- [ ] لا توجد أزرار وهمية أو عمليات حفظ محلية تختفي بعد إعادة التحميل.

## 19. متطلبات تسليم المشروع للمستخدم

سلّم في النهاية:

1. **مستودع مشروع يعمل** مع الواجهة الحالية ولوحة الإدارة والمدونة والتكامل الخلفي.
2. `/admin/login` و`/admin` يعملان على بيئة منشورة، مع **إنشاء حساب مالك آمن بالوسائل الخاصة**، وعدم تسجيل كلمة المرور في README أو المحادثة العامة.
3. قاعدة بيانات مع Migrations وSeed/Import للمحتوى الحالي.
4. مساحة تخزين صور فعلية، ومفاتيح بيئة موثقة بأسماء فقط (`.env.example` دون قيم سرية).
5. تعليمات تشغيل محلية ونشر، وربط النطاق، وإعداد URL للـAuth، والنسخ الاحتياطية والاستعادة.
6. دليل مستخدم عربي مختصر: إنشاء مقال، نشره، إضافة خدمة، تغيير صورة، إضافة قسم، تعديل التواصل، إدارة المستخدمين.
7. اختبارات موثقة ونتيجة قائمة القبول أعلاه، مع ذكر المتطلبات التي لم تُنجز أو ما يحتاج مفاتيح/صلاحيات من مالك الموقع.
8. سجل تغييرات واضح يبيّن الملفات المعدلة وأي اختلاف بصري مقصود عن الأصل.

## 21. تعليمات خاصة بمراجعة التنفيذ

قبل اعتماد النسخة النهائية، يجب أن يراجع المسؤول لوحة الإدارة على حسابه الخاص ويجرب بنفسه أربعة سيناريوهات واقعية:

**السيناريو 1 — تحديث خدمة:** يدخل للإدارة ← الخدمات ← يفتح الخدمة ← يغير الوصف والصورة ← يحفظ مسودة ← يعاين ← ينشر ← يتحقق من صفحة الخدمة للعامة.

**السيناريو 2 — كتابة مقال:** يدخل المدونة ← مقال جديد ← عنوان ومحتوى وصور ← يختار التصنيف وصورة رئيسية وSEO ← يحفظ مسودة ← يعاين ← ينشر ← يتحقق من ظهوره في فهرس المدونة ورابطه المباشر.

**السيناريو 3 — إضافة قسم:** يدخل الصفحات ← الصفحة الرئيسية ← يضيف قسم CTA أو صور ← يغير الترتيب ← ينشر ← يرى القسم الجديد بالهاتف والكمبيوتر.

**السيناريو 4 — تغيير الهوية العامة:** يدخل الإعدادات ← التواصل/الهوية/النبذة ← يغير رابط واتساب أو الصورة العامة ← يحفظ ← يتأكد أن الموقع يعرض القيمة الجديدة، مع بقاء بيانات تسجيل دخوله خاصة.

**إن فشل أي سيناريو لأن التغيير لا يُحفظ في قاعدة البيانات أو لا يظهر في الواجهة العامة، فالنظام ليس مكتملًا.**

## 22. ملاحظات قبل بدء العمل الفعلي

- **مطلوب للمطور:** ملفات المشروع أو رابط المستودع بصلاحية قراءة/تعديل مناسبة، وطريقة الاستضافة الحالية، وأصول العلامة والخط المرخّصة عند الحاجة.
- **مطلوب لربط التخزين والمصادقة:** إعداد مشروع قاعدة البيانات والتخزين وأسماء متغيرات البيئة؛ لا تطلب إرسال المفاتيح السرية داخل محادثة عامة.
- **إن كانت بعض الوظائف مدارة مسبقًا بأداة أخرى:** تكامل معها أو اشرح خطة نقلها دون إيقاف العمل أو تكرار الرسائل والبيانات.
- **قرار التصميم:** استخرج تفاصيل الشعار والألوان أولًا من الشيفرة؛ لا تعتمد أي أرقام ألوان تقديرية واردة في مواصفات خارجية.
- **حدود النطاق:** هذه الوثيقة تُنشئ نظام إدارة للموقع العام ومدونته وخدماته، **وليست** تلقائيًا نظام CRM داخليًا لمعالجة وثائق العملاء أو بياناتهم الحساسة. يمكن دمجه لاحقًا بمواصفات مستقلة وصلاحيات إضافية.

**النتيجة المطلوبة:** موقع «الفزني سيرفيسز» الأصلي، بهويته نفسها، يتحول إلى منصة محتوى وخدمات ومدونة يمكن إدارتها من لوحة واحدة حقيقية وآمنة، دون الحاجة إلى البرمجة في عمليات التحرير اليومية.
